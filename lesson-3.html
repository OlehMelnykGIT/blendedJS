Перебираючі методи масивів

З масиву [1, 2, 3, 4, 5] створити новий масив квадратів: [1, 4, 9, 16, 25].

  • map викликає колбек для кожного елемента і збирає те, що він повернув, у новий масив тієї ж довжини.
  • ** — піднесення до степеня, тобто n ** 2 те саме, що n * n.
  • Змінна називалась dubleNumbers, але тут квадрати, а не подвоєння. Краща назва: squares.

З масиву об'єктів { id, values: [...] } зібрати всі values в один масив: [1, 2, …, 9].

  • flatMap = map + розплющення на один рівень. Масиви, які повернув колбек, зливаються в один.
  • map тут дав би [[1, 2, 3], [4, 5, 6], [7, 8, 9]].
  • Перший варіант: (element) => { element.values; }. У фігурних дужках потрібен return, інакше колбек повертає undefined. Запусти код вище й подивись на останній рядок.

Перевірити, чи є в масиві людей хоча б один з віком менше 20. Очікуваний результат: true.

  • some зупиняється на першому true, решту елементів не перевіряє.
  • Для порожнього масиву повертає false.

Перевірити, чи кожен елемент масиву [2, 4, 6, 8, 10] парний. Очікуваний результат: true.

  • every — протилежність some: зупиняється на першому false.
  • Для порожнього масиву повертає true, бо жодного «поганого» елемента немає.
  • Параметр колбека названий так само, як масив (numBers), і перекриває його. Назви параметр в однині: number.

Знайти перше непарне число в масиві [2, 1, 6, 8, 9, 10, 12]. Очікуваний результат: 1.

  • find повертає сам елемент, а не true, і зупиняється на першому збігу.
  • Якщо нічого не знайдено, повертає undefined. Індекс елемента шукає findIndex.
  • Умова el % 2 === 0 шукає парне число, тому вийде 2 замість 1. Для непарного потрібно !== 0.
  • getFindNumber(arry) всередині працює з numbErs, а не з параметром arry. Функція ігнорує те, що їй передали. Та сама історія в задачах 6 і 7.

Відсортувати [4, 2, 5, 1, 3] за зростанням. Очікуваний результат: [1, 2, 3, 4, 5].

  • Функція порівняння повертає число: від'ємне ставить a перед b, додатне ставить b перед a, 0 лишає порядок.
  • toSorted повертає новий масив. Старий sort сортує той самий масив.

Відсортувати ["banana", "orange", "apple", "pear"] за алфавітом.

  • a.localeCompare(b) сам повертає від'ємне число, 0 або додатне, тобто саме те, що чекає toSorted.
  • Він враховує правила мови, тому правильно сортує літери на кшталт ґ та і.

Відсортувати масив користувачів за віком за зростанням.

  • Порівнюємо не самі об'єкти, а їхні поля: a.age - b.age.

Створити новий масив лише з тих об'єктів, де вік більше 20.

  • filter лишає елементи, для яких колбек повернув true. Якщо нічого не підходить, повертає порожній масив [], а не undefined.
  • Методи, що повертають масив, можна з'єднувати в ланцюжок: filter(...).map(...).

Обчислити суму елементів масиву [1, 2, 3, 4, 5].

  • reduce(колбек, початкове значення). Колбек отримує акумулятор (результат попереднього кроку) і поточний елемент, а повертає новий акумулятор.
  • Другий аргумент 0 — це початкове значення. Без нього reduce на порожньому масиві кидає помилку.
  • У lesson-3.js цю задачу ще не розв'язано. Вище готове рішення.

Класи

Клас — це «креслення», за яким new створює однакові за будовою об'єкти зі спільними методами.

  • constructor запускається один раз на кожен new і заповнює властивості через this.
  • Методи, оголошені в класі, не копіюються в кожен об'єкт: вони спільні для всіх екземплярів.

Клас Calculator з методами number, add, subtract, multiply, divide і getResult. Усі, крім getResult, повертають this. divide(0) має кинути помилку.

  • Ланцюжок працює, бо кожен метод повертає this, тобто той самий об'єкт. Наступний .add() викликається вже на ньому.
  • getResult повертає число, тому він завжди останній у ланцюжку.
  • throw new Error(...) зупиняє виконання. Перехопити помилку можна через try...catch.
  • За умовою divide(0) має викидати помилку, а в lesson-3.js там console.log("Error!"). Ланцюжок у такому разі йде далі з неправильним значенням.

Клас Client з приватними #login і #email. Доступ до них лише через геттери й сеттери login та email.

  • Поля з # доступні тільки всередині класу. Звернення client.#login зовні — це синтаксична помилка.
  • get і set виглядають як звичайна властивість (client.login), але всередині це методи. Туди зручно додати перевірку.

Клас Person (name, age, gender, email) з методом getDetails(). Клас Employee розширює Person, додає salary й department і має метод getEmployeeDetails().

  • extends дає нащадку всі методи батька. Тому employee.getDetails() працює, хоча в Employee такого методу немає.
  • У конструкторі нащадка super(...) треба викликати до першого звернення до this.
  • { salary, department, ...personData } бере два поля, а решту збирає в новий об'єкт для super.
  • Твій варіант { ...super.getDetails(), salary, department } теж правильний, якщо потрібні всі дані разом.
