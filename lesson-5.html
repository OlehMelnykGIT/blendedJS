Список справ: форма додає картку, кнопка «Delete» її прибирає, список і тема переживають перезавантаження сторінки. Код розбитий на модулі (import / export), проєкт збирає Vite. Сам застосунок запускається з папки lesson-5-vite командою npm run dev. Тут код кожного модуля з поясненнями, а в кінці весь застосунок одним блоком, який можна запустити в пісочниці.

Допоміжні модулі

Зібрати всі потрібні DOM-елементи в один об'єкт refs.

  • Елементи шукаються один раз, коли модуль імпортують уперше. Далі будь-який файл бере їх через import { refs } from './refs'.
  • Скрипт підключено як type="module", а такі скрипти виконуються після розбору HTML. Тому елементи вже є на сторінці.

Функції для збереження й читання даних. Ключі — константами.

  • localStorage зберігає тільки рядки. Масив об'єктів перетворюємо на JSON-рядок перед записом і назад після читання.
  • Якщо ключа немає, getItem повертає null. Функція одразу його повертає, і в tasks.js спрацьовує || [].
  • Ключі в константах: одна помилка в рядку 'taks' — і дані «зникли». З константою такого не буде.
  • Якщо в сховищі лежить зіпсований рядок (не JSON), JSON.parse кине помилку, і застосунок не запуститься. Захист: обгорнути в try { … } catch { return null; }.

Намалювати картки для всього масиву задач.

  • map робить з кожної задачі рядок розмітки, join('') склеює їх в один.
  • innerHTML = замінює весь вміст списку. Тому після будь-якої зміни масиву викликаємо renderTasks(tasks), і сторінка завжди збігається з даними.
  • За ТЗ розмітка мала бути в markup-tasks.js, а він порожній. Можна винести туди createMarkup(array), яка повертає рядок, а в render-tasks.js лишити тільки refs.task.innerHTML = createMarkup(array).
  • Одруківка: elemet → element (або просто task).
  • Текст від користувача потрапляє в innerHTML. Якщо ввести в назву <img src=x onerror=alert(1)>, код виконається. Для навчального проєкту нормально, але в реальному треба екранувати текст або ставити його через textContent.

Логіка задач

Після «Add» задача додається до списку й у localStorage. Порожні поля й повтор назви не пропускаємо, поля після додавання очищаємо.

  • getFromLs(...) || []: якщо в сховищі нічого немає (null), починаємо з порожнього масиву. Це заміна закоментованого if / else.
  • event.target.elements.taskName — поле форми за атрибутом name. trim() прибирає пробіли, щоб назва з одних пробілів вважалась порожньою.
  • some повертає true, щойно знайде хоч одну задачу з такою назвою. Порівнюємо через toLowerCase(), тож «Купити» і «купити» — теж повтор.
  • Порядок завжди однаковий: змінили масив → renderTasks → saveInLS.
  • event.target.reset() очищає всі поля форми.
  • deleteTask шукає задачу за назвою: tasks.filter(el => el.title !== h3Value). Фільтр прибирає кожну задачу з такою назвою. Якщо назви унікальні, такого вже не буде.
  • Задачі, що вже лежать у localStorage з однаковими назвами, перевірка не прибере. Видали їх один раз (DevTools → Application → Local Storage) або натисни Delete.

Кнопка «Delete» прибирає свою картку зі списку і з localStorage.

  • Обробник висить на всьому #task-list (делегування). Картки перемальовуються, а обробник лишається той самий, тож вішати його на кожну кнопку не треба.
  • Перевірка класу кращий варіант, ніж nodeName !== 'BUTTON' із першої версії: якщо в картці з'явиться ще одна кнопка, вона не видалятиме задачу.
  • nextElementSibling кнопки — це h3, з нього беремо назву. filter повертає новий масив без цієї задачі, тому tasks оголошено через let.
  • nextElementSibling залежить від порядку в розмітці: поміняєш місцями кнопку і заголовок — і видалення зламається. Надійніше: evt.target.closest('.task-list-item').querySelector('h3').textContent.

Інший спосіб розв'язати проблему однакових назв: дати кожній задачі власний id і видаляти за ним. Тоді назви можуть повторюватись.

  • Date.now() — кількість мілісекунд від 1970 року. Двічі за одну мілісекунду задачу не додаси, тож число унікальне.
  • Так роблять у реальних проєктах: назву можна змінити або повторити, а id лишається. Перевірка унікальності назви тоді потрібна тільки якщо цього хоче ТЗ.
  • У старих задач у localStorage id немає. Після такої зміни сховище треба очистити.

Тема і точка входу

Кнопка міняє клас body між theme-dark і theme-light. Вибір зберігається.

  • У HTML на body вже стоїть theme-dark. Тому initTheme досить перевірити лише світлу тему.
  • Коротший варіант перемикання: classList.toggle на обидва класи. const isDark = document.body.classList.toggle('theme-dark'); document.body.classList.toggle('theme-light', !isDark);
  • У гілці else були зайві фігурні дужки { { … } }. Код працює, але їх варто прибрати (тут уже прибрано).

Підключити модулі, відновити дані зі сховища й повісити обробники.

  • main.js тільки з'єднує частини. Уся логіка лежить в окремих модулях.
  • Спочатку initTasks і initTheme: сторінка одразу показує збережений стан.
  • Функції передаємо без дужок (addTask, а не addTask()): їх викличе браузер, коли станеться подія.

Усе разом

Ті самі модулі, склеєні в один скрипт, щоб запустити тут, без Vite. Замість iziToast — повідомлення в консолі. Додай задачі, спробуй повтор назви, а потім натисни «Запустити» ще раз: сторінка почнеться спочатку, а задачі й тема відновляться з localStorage.

  • Пісочниця працює на тому ж сайті, що й конспект, тому бачить той самий localStorage. Застосунок на Vite (localhost:5173) — інший сайт, у нього своє сховище.
  • Щоб почати з нуля, допиши в кінець localStorage.clear() і запусти один раз.
